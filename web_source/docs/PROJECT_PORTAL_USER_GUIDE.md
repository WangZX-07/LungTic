# LungTic 项目进度门户使用手册

本手册面向项目管理员和项目成员，说明飞书登录、部门/职位角色映射、项目进度填报和 GitHub 同步的日常操作。项目门户只管理 LungTic 项目进度，不授予临床系统或病例访问权限。

部署后的同内容网页帮助中心位于 `https://project.respulse.top/#/help`，也可从网站左侧“使用帮助”或“我的 → 使用帮助”进入。

## 1. 第一次登录

1. 在浏览器或飞书工作台打开 `https://project.respulse.top`。
2. 使用飞书完成授权登录。首次登录会同步当前飞书账号的姓名、部门和职位。
3. 首位引导管理员进入 **项目设置**；其他未匹配角色的成员会看到“尚未映射项目权限”。
4. 如果飞书管理员刚修改了某人的部门或职位，该成员应先退出项目门户，再重新登录一次，才能刷新组织信息。

## 2. 部门 ID 到底填什么

本项目统一使用飞书 `open_department_id`：

- 正确格式：`od-` 开头，例如 `od-4e6ac4d14bcd5071a37a39de902c7141`。
- `ou_...` 是用户 Open ID，不能填到部门 ID。
- `cli_...` 是飞书应用 ID，不能填到部门 ID。
- `0` 是飞书根部门标识，不能作为本项目的成员部门映射条件。
- 不要把 `od-...` 填入“职位 ID”。

### 推荐获取方法

1. 让需要加入项目的成员先登录项目门户一次。
2. 管理员打开 **项目设置 → 项目成员**。
3. 在成员姓名下方找到以 `od-` 开头的值。
4. 点击 **复制部门 ID**。
5. 点击 **新增规则**，粘贴到 **飞书部门 open_department_id**。

如果成员属于多个部门，页面会显示多个 `od-...`。为每个希望授予权限的部门分别建立规则；成员命中任意一条规则即可获得该规则的角色。

### 飞书开放平台备用方法

也可以使用飞书开放平台“获取子部门列表”或“搜索部门”接口，明确选择 `department_id_type=open_department_id`，复制返回的 `open_department_id`。不要复制自定义 `department_id`，因为本项目同步和匹配均固定使用 `open_department_id`。

## 3. 创建角色映射规则

进入 **项目设置 → 飞书部门与职位映射 → 新增规则**。

| 字段 | 填法 |
|---|---|
| 规则名称 | 能看懂即可，例如“研发部项目成员” |
| 飞书部门 open_department_id | 从项目成员列表复制的 `od-...` |
| 飞书职位 ID | 仅在成员信息确实同步了职位 ID 时填写；不能填 `od-...` |
| 职位名称 | 按飞书通讯录中的完整职位文本匹配，例如“技术负责人” |
| 项目角色 | 选择该规则授予的项目权限 |
| 优先级 | 数字越大越优先，建议普通成员 100、组长 200、项目负责人 300 |

规则示例：

| 目标 | 部门 ID | 职位 | 角色 | 优先级 |
|---|---|---|---|---|
| 研发部所有项目成员 | `od-研发部实际值` | 留空 | 项目成员 | 100 |
| 研发部技术负责人 | `od-研发部实际值` | 职位名称“技术负责人” | 小组负责人 | 200 |
| 项目办公室负责人 | `od-项目办实际值` | 留空 | 项目负责人 | 300 |

同一条规则内填写多个条件时是“并且”关系。例如同时填部门和职位，成员必须同时属于该部门且职位完全一致。一个成员命中多条规则时，优先级最高的规则生效。

需要给某个人临时指定角色时，可以在 **项目成员** 的角色下拉框中手动选择。手动角色优先于自动映射；清空下拉框后恢复自动映射。

## 4. “职位未同步”是什么意思

项目门户读取飞书通讯录用户资料中的职位字段。显示“飞书资料未填写职位”通常表示部门已经成功同步，但该成员的飞书通讯录资料没有填写职位；显示“部门也未同步”则更可能是通讯录权限或应用可用范围不完整。

处理顺序：

1. 飞书企业管理员进入管理后台的组织架构/成员管理，打开该成员资料，确认“职位”已有值并保存。
2. 飞书开放平台进入该自建应用的 **权限管理**，确认应用具备“获取单个用户”Contact v3 所需的通讯录读取权限。
3. 在应用的通讯录可用范围中包含该成员及其部门，重新发布应用并完成管理员审核。
4. 让该成员退出项目门户并重新登录，再到项目设置查看。

如果暂时不需要按职位细分，直接只填部门 ID 建规则即可；职位字段可以全部留空。

> 注意：截图中显示“任意部门 · 职位 0”和“任意部门 · 职位 od-...”说明值填到了错误字段。请删除这两条规则，用 `od-...` 重新填写“飞书部门 open_department_id”，职位留空。

## 5. 项目角色

| 角色 | 主要权限 |
|---|---|
| 项目管理员 | 管理成员、映射规则、集成及全部项目数据 |
| 项目负责人 | 管理里程碑、任务、风险、决策和全部进度 |
| 小组负责人 | 创建/分配任务，更新任务和风险，提交进度 |
| 项目成员 | 查看项目、更新本人任务、提交本人进度、登记风险 |
| 观察者 | 只读查看 |
| 未分配 | 不能进入项目数据，等待管理员配置 |

## 6. 日常使用

- **总览**：查看总体完成度、近期进度、风险和里程碑。
- **任务**：负责人分配任务；成员更新本人任务状态和完成比例。
- **进度**：填写本期完成、下一步、阻塞项和证据链接。
- **动态**：查看 GitHub Webhook 收到的 Push、PR、Issue、工作流和 Release。
- **风险与决策**：记录风险等级、处置方案和关键项目决策。
- **我的**：检查本人同步到的部门、职位、角色和 GitHub 账号。

## 7. GitHub 动态没有内容

“GitHub Webhook 已配置”只表示服务器环境变量完整，不代表已经收到事件。Webhook 只接收配置完成后的新事件，不会自动补历史记录。

1. 在 GitHub 仓库 **Settings → Webhooks → 对应 Webhook → Recent Deliveries** 检查投递。
2. 正常投递应返回 HTTP `202`。
3. 新建一次测试提交、Issue 或 PR 后刷新项目门户动态页。
4. 如果出现 `401/403`，核对 GitHub Webhook Secret；如果 Secret 曾发到聊天或截图中，应立即重新生成并同时更新 GitHub 与服务器。

## 8. 常见问题速查

| 现象 | 处理 |
|---|---|
| 成员列表没有某人 | 让该成员先通过飞书登录一次 |
| 部门 ID 为空 | 检查通讯录权限、应用可用范围、应用是否已发布，然后重新登录 |
| 职位未同步 | 在飞书成员资料中填写职位；或只按部门映射 |
| 自动角色未分配 | 检查 `od-...` 是否填在部门字段、规则是否启用、优先级是否正确 |
| 改规则后角色仍不对 | 先检查成员是否设置了手动角色；手动角色优先 |
| 飞书组织信息刚修改但页面没变 | 退出门户并重新登录，触发同步 |
| GitHub 已配置但动态为空 | Webhook 不补历史；制造新事件并检查 Recent Deliveries |

## 9. 安全注意事项

- App Secret、GitHub Webhook Secret、数据库密码只保存在服务器受限环境文件中。
- 不要把任何 Secret 发到聊天、截图、文档或 GitHub 仓库。
- 飞书应用只申请项目门户所需的最小通讯录权限，并限制应用可用范围。
- 项目角色与临床病例权限完全隔离，项目管理员不会因此获得病例读取权限。
